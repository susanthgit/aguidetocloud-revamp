## About this study guide

The **Certified Open Source Developer for Enterprise (CODE)** certification assesses how developers work with open source software inside an organisation. Its scope goes beyond writing code: candidates must understand licensing, dependency intake, contribution workflows, project health, governance and the operational controls that support responsible use.

This is an independent Guided study resource. Its questions and explanations are original and grounded in public primary documentation; they are not official, recalled or reconstructed exam items. The Linux Foundation owns its certification names and marks. This resource is not affiliated with or endorsed by The Linux Foundation and uses no official logo or badge.

### Fundamentals of Open Source Software Development

Understand how open source projects differ from merely source-available software, how communities organise work, and how maintainers, contributors, users and organisations interact. Be ready to reason about repositories, issue and change workflows, project governance, release practices, semantic versioning and the evidence used to judge project health.

### Open Source Licensing and Usage Guidelines

Study licence permissions, conditions, notices and distribution obligations without treating a short label as a substitute for the licence text. Distinguish copyright licences from trademarks, patents, contributor agreements and Developer Certificate of Origin sign-offs. For uncertain ownership, export or licence questions, know when organisational policy or qualified counsel must decide.

### Consuming Open Source Software

Focus on dependency selection, provenance, versions, transitive risk, vulnerability response and repeatable builds. Understand what software bills of materials, checksums, signatures and attestations can establish—and what they cannot guarantee. Practise evaluating whether a project is suitable for a specific operational and support context rather than relying on popularity alone.

### Contributing to Open Source

Know how to read a project's contribution rules, create focused changes, communicate respectfully, respond to review and preserve the project's technical and social conventions. Separate the right to use code from the process required to contribute it. A DCO sign-off records a contribution statement; it is not a copyright assignment.

### Open Source Management Operations

Study the repeatable organisational work behind open source use: policy, intake, inventory, review, exception handling, education, metrics and incident response. Understand how an open source programme office can coordinate legal, security, engineering and procurement responsibilities without replacing those functions.

## A practical study plan

1. **Map the blueprint.** Create five notes matching the official domains and record each concept under one primary domain.
2. **Read the evidence.** For every dependency decision, identify the licence text, release source, version, provenance and project policy that supports it.
3. **Practise small workflows.** Review a public repository's contribution guide, issue template, release tags, security policy and governance documents.
4. **Explain control limits.** State what an SBOM, signature, scanner, policy or review proves, then state what remains unknown.
5. **Use scenario reasoning.** Choose the next defensible action for the organisation and project, not the option with the most open source vocabulary.

Spend the most time on consuming open source software, the largest domain at 28%, then contribution and development fundamentals. Keep licensing answers precise: the correct response often depends on the exact licence, version, distribution model and organisation policy.
